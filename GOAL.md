# GOAL.md — Anneal autonomous build directive

**You are building Anneal**, a target-agnostic web QA engine. Work autonomously, milestone by milestone, until `./verify.sh all` exits 0.

## Frozen inputs (read first, never re-litigate)
- **HLD.md** — the *why*. Decision register D1–D37 is **frozen**. Extend, never re-open a decision.
- **LLD.md** — the *how*. Package layout, DDL, schemas, compiler, interpreter, error table, incident machine, scheduler, API. This is your implementation contract.
- **schemas/bundle.schema.json**, **schemas/step-event.schema.json** — normative contracts, validated on every write.
- **fixtures/campaign-crud.bundle.jsonc** — the normative Bundle example and **M0's golden input**. The Bundle schema was derived from it; if code and fixture disagree, the fixture wins.

## The definition of DONE
`./verify.sh <milestone>` **exits 0**. Nothing else. The model's opinion that a thing "looks done" does not count — the gate does. Build to make the gate pass, in order: `m0 → m1 → m2 → m3 → m4`. `./verify.sh all` runs every gate as a regression sweep and finishes with the **typed API contract gate**; earlier milestones must stay green as later ones land.

**The corpus is the capability bar (closes D30).** The milestones prove the engine works; the corpus proves it is capable. The mandatory bar: **P1–P5 must be green and N1 must be RED** (`parity/corpus/*.nl.txt`), each authored through the hot lane and run on the hermetic golden target — plus the property gates (determinism across K≥3 reruns, <30s cold replay, N1-red oracle honesty, zero residue). Generalization beyond the corpus is proven by the opt-in holdout gate (`ANNEAL_HOLDOUT_DIR=/path ./verify.sh holdout`), which authors flows the engine has never seen against a target you supply. Do not treat the build as done until `./verify.sh all` is green.

## Environment & LLM keys
- **Both providers have working keys** (Anthropic **and** OpenAI), read from the environment via the standard SDK vars (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`) — never hardcode; they live in a gitignored `.env`. This unblocks the intelligent lanes: **M2** (hot-lane NL authoring + calibration) and **M3** (warm-lane heal). The earlier gpt-5.5-only fallback no longer applies.
- The `anneal-llm` package (LLD §, `A15+B6` seam) already does provider fallback. **Default the hot/warm lanes to a current top-tier Claude model** (e.g. `claude-opus-4-8`) for authoring/heal quality, with OpenAI as the fallback the seam provides. Model choice is config, not a frozen decision — keep it in one place, not scattered.
- **M0 and M1 need no keys** (contracts + cold lane are zero-LLM by construction, D31) — launch the loop before wiring keys if you want; they gate M2 onward.

## Working rules
1. **Fixture-first, contract-first.** M0 ships the DDL (incl. all four concurrency primitives, LLD §3.1), both JSON schemas, the compiler, the cold interpreter skeleton, `anneal export`, and the hermetic **golden app** (`fixtures/app/`). Do not start M1 until `./verify.sh m0` is green.
2. **The cold-lane dependency rule is load-bearing (D31).** `anneal-executor` must **not** depend on `anneal-llm`. `verify.sh m0` asserts it. Reach intelligence only through the `Healer`/`Author` Protocols in `anneal_core.ports`, injected into `Interpreter.warm/.hot`.
3. **Transplant, don't invent.** Every NUANCES COPY entry is vendored in M0/M1 before writing a replacement becomes tempting. Log any deviation from a manifest entry — or from the HLD/LLD — in `implementation-notes.md` with the conservative call you made. Phase acceptance = gate green **plus** those notes reviewed (HLD §15).
4. **Take defaults; keep it minimal.** No feature beyond the milestone's scope (HLD §15 table, LLD §12). Chromium-only, one viewport, single default param row, single org (D17, D22, D23).
5. **Commit per milestone** when its gate goes green: `M<n> green: <one line>`.
6. **Never guess an oracle or an interview answer.** Unanswered authoring-interview questions block the freeze (D26). If a *design* question genuinely blocks you and neither HLD nor LLD answers it, stop and surface it — do not invent a decision.
7. **The bar is frozen. Never edit it to pass a gate.** These files are READ-ONLY to you: `verify.sh`, `baseline.json`, `schemas/*.json`, `fixtures/campaign-crud.bundle.jsonc`, `parity/corpus/*`, HLD.md, LLD.md, NUANCES.md. You may create the harness that *runs* the checks (the golden app, pytest files behind the markers) — you may **never** weaken a check, lower a threshold, delete a corpus flow, or make N1 pass. `verify.sh` self-checks this and will hard-fail. If a gate looks wrong, **stop and surface it** — changing the bar to go green is the one unrecoverable failure.
8. **Maker ≠ checker (review each milestone before proceeding).** When a milestone gate goes green, before starting the next one, spawn a strict reviewer sub-agent (fresh context, adversarial instructions) to read that milestone's diff against HLD/LLD/NUANCES and `implementation-notes.md`. It rejects on contract drift, on a NUANCES COPY entry rewritten from memory instead of vendored, on code no one could later debug, and **on overfit — any code path, hardcoded value, or prompt example that ties the engine to the corpus flows or the demo app's specific DOM.** Its findings become the next things to fix. `verify.sh` proves it works; the reviewer proves it is the thing we designed.
9. **No overfitting. Target-agnostic is load-bearing and gate-enforced.** The engine must contain ZERO app-specific literals — routes, testids, flow choreography, or few-shot prompt examples tied to any one target or the corpus flows. App specifics live in TargetProfile / TerritoryNotes **data** only. `verify.sh check_target_agnostic` (frozen, runs before every gate) enforces this — it will hard-fail a milestone that leaks a target literal into engine code. You will ALSO be evaluated on a **held-out set of flows you never see**: `./verify.sh holdout` (run by the human against `$ANNEAL_HOLDOUT_DIR` — real flows kept outside this repo) authors each unseen NL flow through your hot lane and asserts it replays to its expected verdict. Build for generality; **an engine that passes only the corpus is a failure even with a green gate.** Deliverable: implement the `holdout` pytest marker (read `$ANNEAL_HOLDOUT_DIR`, author each `*.nl.txt` via the hot lane against its named target, assert the expected verdict from `holdout.json`) so the human can run it at M2+ acceptance. The marker's runner is yours to write; the flows are not — you never populate that dir.

## Milestone exit criteria (mirror of HLD §15; the gate enforces them)
- **M0 — Contracts:** the fixture validates against the schema, compiles to a step plan, and **replays green against the golden app** with postcondition waits; trace + video captured; `anneal export` prints the matching standalone Playwright script; the cold executor has no LLM in its dependency graph; the target-agnostic grep audit passes; the vendored ladder/harness files import cleanly.
- **M1 — Cold lane + console v0:** a read-only suite runs in parallel, green, each test in seconds, inspectable in the console (runs list + detail: NL intent ↔ frames ↔ network); an expired session parks the suite `AUTH_EXPIRED` before any test runs; CLI run/status/export; retention prune works.
- **M2 — Hot lane:** a CRUD flow authored from NL alone (console or CLI) freezes, calibrates (negative-control + network discriminativeness), and replays green twice with distinct tokens and zero residue; the ambiguity interview blocks on unanswered questions; the destructive guard holds.
- **M3 — Red path:** against a deliberately drifted target — a testid rename auto-heals as one incident changelog line; a fallback-rung pass opens a re-freeze incident; a form redesign yields one incident whose ruling (with `ruling_note`) propagates to all members or rolls back cleanly; budgets + oscillation stop hold; drain-all-drifts in one heal session.
- **M4 — Scale:** full suite on one workspace, parallel, with the `exclusive` advisory lock and suite-end sweeper; ENV heuristics park correctly; change-driven selection picks the run set from an NL change description with per-test reasons.

Start at M0. Make `./verify.sh m0` exit 0.
